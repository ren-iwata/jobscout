# 10_product_vision — JobScout 全体像（SaaS構想・完成形の共有）

制定: 2026-07-19（CEOとの全体像すり合わせ。実装順序の約束ではなく「正しい地図」の共有が目的）

## 完成形の一言定義

フリーランサーの**成果物そのものから能力を導出し**、本人が自分の能力を説明できなくても、案件の発見→選別→応募→顧客対応→受注→開発引き渡し→結果学習までを、プラットフォーム規約の許す限界までエージェント化するサブスクリプションサービス。

## 中核技術=能力分析エンジン（Capability Analyzer）【SaaSの本丸・最大の差別化】

「利用者の活動を把握していないとエージェントできない」——その通りで、把握は自己申告ではなく**成果物の直接分析**で行う。

- 入力: GitHubリポジトリ接続（OAuth）・公開URL・ストア/デモリンク・職務経歴の補助テキスト
- 分析: ①コード実体の解析（言語・フレームワーク・アーキテクチャパターン・テストの有無・CI/CD・規模・更新鮮度・本人のコミット比率）②稼働検証（URLが実際に動くか・応答・SSL・健全性——「主張」でなく「事実」）③LLMによる能力への翻訳（「何を作ったか」→「何ができるか」→「どの案件タイプに適合するか」→「価格バンド推定」）
- 出力: **検証済み能力レジストリ**（evidence＋能力マップ＋適合案件プロファイル＋単価バンド）
- 継続把握: 接続先の定期再分析／webhookで「活動の把握」を自動維持（作れば作るほどプロフィールが勝手に強くなる）
- 戦略的意味: これはAgentFront企画書の「能力証明・評価変換」と同一部品。**両製品で共有する会社の基盤資産**であり、AtoA構想Phase 3（能力ベースマッチング）の土台になる。JobScoutとAgentFrontは同じ能力レジストリの上に立つ双子。

当社での現状（正直な棚卸し）: 現在のプロフィールはCTOが会社の書庫（社史・各リポ・本番URL）から手作業で写した静的スナップショット。CEO単独利用の間は正確（会社の実体がファイルなのでCTOが完全把握しており、新しい成果物が出るたび更新できる。書庫からの自動生成も当社なら容易）。**SaaSではこの手作業が成立しないから、能力分析エンジンが本丸になる。**

## 層別の完成形

### 1. 取り込み層（「何を検索するか」→「検索すら不要」へ）
- v0.2（現在）: 検索結果ページ丸ごと貼り付け→分割→採点→上位フル分析
- 次: **検索クエリの自動生成**（能力レジストリ＋戦略から「今日の検索」を提示。プラットフォーム別・鮮度別）
- v0.3: **通知メール自動取り込み**（保存検索の通知メール→自動分析→朝には「今取るべき」が並ぶ）→ 手動搬入の消滅。残る一回作業=保存検索の設定（このとき検索クエリ生成が設定ガイドになる）
- 将来: Upwork公式APIの利用申請（承認されれば正規の自動取得。商用SaaSとしては必須の検討事項）
- 消せない層: 応募・送信のクリック、金銭操作（プラットフォーム規約。ここを越えると全利用者のアカウントを危険に晒すため、製品として永久に越えない）

### 2. 判断層（現在ほぼ完成）
6分類×8軸判定・危険検出・単価基準見積もり。今後は結果学習（下記5）で判定精度が個人最適化される。

### 3. 顧客対応層（規約内で最大限のエージェント化）
- 現在: 返信ドラフター（貼る→案→コピー送信・【要判断】注意付き）
- 次: **交渉レンジの事前承認**——価格・納期の許容レンジを利用者が予め承認し、レンジ内の交渉は自動起案・レンジ外のみ人間判断（AgentFrontの人間承認ゲート思想の移植）
- 次: 面談準備ブリーフ（面談前に想定問答・論点・見せる実績を自動生成）
- 検討: ブラウザ拡張による読み取り・下書き挿入補助（送信クリックは常に人間。規約の縁なので商用提供前に法務確認）
- 自前チャネル（AgentFront）では完全AI対応が合法——両翼構造。JobScoutで実績を作り、AgentFrontへ顧客を還流させる

### 4. 受注後層（開発〜納品の一気通貫）
WON→Work Contract自動生成（実装済み）→開発実行体（当社ではCTO・将来は利用者自身のAI開発環境や外部ビルダー）→納品物・納品メッセージ案→検収→結果記録。agentfront保留中の「金と納品のライン」部品（契約書・請求書・検収書テンプレ）はここに合流する。

### 5. 学習層（結果からの自己改善）
応募記録（実装済み）→蓄積後: 返信率・勝率・価格帯・実績別の有効性ダッシュボード→提案文・プロフィール・検索クエリ・判定基準への改善提案。「市場価値は低いのか未測定なのか」への実データの答え。

### 6. あったらいい機能の地図（順不同・着手約束ではない）
- **プラットフォームプロフィール自動生成**: Upworkバイオ（英）・CW自己紹介（日）を能力レジストリから生成・結果学習で改善
- ポートフォリオページ自動生成（応募に貼る証拠URLの集約ページ。AgentFront受付ページと統合可）
- 見積もり学習補正（実工数記録→工数推定の個人補正）
- スカウト対応（届いたスカウトの評価・返信案）
- 辞退・見送りの定型文生成／応募文のA/Bバリアント
- 多言語展開（英語圏フリーランサー向け＝Upwork単体市場）

## サブスク化への段差（正直なリスト）

1. まずCEO自身の受注実績（単独利用で装置を磨き「作った本人が稼いだ装置」にする——最強の営業素材）
2. 能力分析エンジン（共有基盤・AgentFrontにも効く。SaaS化判断の前でも作る価値がある）
3. マルチテナント化: 認証・データ分離・オンボーディング（成果物URLを貼るだけで初期プロフィール完成、が理想体験）
4. 課金（Stripe・プラン設計はLLM原価から: 1分析≒数円〜数十円）
5. 商用時の規約・法務再点検（Upwork API正式申請・利用規約・特商法）

## 実装順の現在提案（CEO裁定待ちの参考）

直近: 検索クエリ生成（小）→ v0.3メール取り込み（①の消滅）→ 交渉レンジ承認 → 能力分析エンジン（大・基盤）→ 結果学習ダッシュボード（データが溜まった頃）→ マルチテナント（SaaS判断後）
